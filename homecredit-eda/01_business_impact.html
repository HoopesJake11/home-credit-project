Purpose. This notebook asks what the model’s scores would mean for an actual lending decision. It turns the final model’s holdout predictions into default rates by risk group, the effect of flagging the riskiest applicants, and a comparison with a simple “no credit history, no loan” rule. It follows the success definition in the business problem statement: a lower default rate at the same approval rate, or a higher approval rate at the same default rate.

Data and model. Everything here uses the 61,502 holdout applicants the model never saw in training, so nothing is in-sample. The model is a refit of the final XGBoost model from modeling.qmd with the same hyperparameters, built by rebuild_presentation_cache.R. Its holdout AUC is 0.7550, against 0.7556 in the original run; the small gap comes from package-version differences.

How to read the results. Every policy below is a retrospective comparison on historical applicants whose outcomes are already known. These are illustrations of what the ranking could support, not measured results of a deployed policy. No costs, revenue, or loan pricing are included.

1. Default rate by model risk decile

Applicants are ranked by predicted risk and split into ten equal groups (deciles). If the model ranks well, the default rate should rise steadily from decile 1 (safest) to decile 10 (riskiest).

deciles <- ho |>

  mutate(share_of_defaults = defaults / sum(defaults),

2. Flagging the riskiest applicants

Each row below flags the riskiest 5%, 10%, 15%, or 20% of holdout applicants and shows what happens to the default rate among everyone else. “Flagged” could mean declined, referred to an underwriter, or asked for more verification; the table does not assume which.

flag_policy <- function(q) {
  cutoff <- quantile(ho$prob, 1 - q)
  flag   <- ho$prob >= cutoff
  tibble(
    flagged_share         = mean(flag),
    defaults_caught       = sum(flag & ho$default == 1) / sum(ho$default),
    default_rate_flagged  = mean(ho$default[flag]),
    default_rate_approved = mean(ho$default[!flag]),
    relative_drop         = 1 - mean(ho$default[!flag]) / base_rate,
    good_borrowers_flagged = sum(flag & ho$default == 0) / sum(ho$default == 0),
    defaults_avoided_per_10k = sum(flag & ho$default == 1) * per_10k,
    defaulted_credit_avoided_per_10k = sum(ho$credit[flag & ho$default == 1]) * per_10k,
    score_cutoff          = cutoff
  )
}
policies <- map_dfr(c(0.05, 0.10, 0.15, 0.20), flag_policy)

policies |>
  mutate(across(c(flagged_share:good_borrowers_flagged), ~ pct(.x)),
         across(c(defaults_avoided_per_10k, defaulted_credit_avoided_per_10k), num),
         score_cutoff = round(score_cutoff, 3)) |>
  knitr::kable(caption = "Flagging the riskiest X% of applicants")

3. Same approval rate: the model vs. “no credit history, no loan”

A traditional lender turns away anyone without a credit bureau record. This compares that rule with the model turning away the same number of applicants, namely the ones it rates riskiest.

Which applicants count as “no credit history”. The rule here declines every applicant with no credit bureau record (has_bureau_record == 0), which is 14.3% of the training data. This is a broader group than the thin_file feature in data_preparation.R, which flags applicants with no bureau record and no credit inquiry data. The thin_file feature is not used in this comparison.

What kind of comparison this is. It is retrospective: both policies are applied to historical holdout applicants whose outcomes are already known. The “no credit history, no loan” rule is a simplified benchmark, not Home Credit’s actual policy, and outcomes exist only for loans that were actually issued.

rule_decline  <- ho$has_bureau == 0
k             <- sum(rule_decline)
model_decline <- rank(-ho$prob, ties.method = "first") <= k

same_approval <- tibble(
  Policy = c("No credit history, no loan", "My model"),
  `Approval rate` = pct(c(1 - k / n_ho, 1 - k / n_ho)),
  `Default rate of approved loans` = pct(c(mean(ho$default[!rule_decline]),
                                           mean(ho$default[!model_decline])), 2),
  `Defaults per 10,000 applicants` = num(c(sum(ho$default[!rule_decline]),
                                           sum(ho$default[!model_decline])) * per_10k),
  `No-bureau-record applicants approved` = pct(c(0, mean(!model_decline[ho$has_bureau == 0])))
)

# Same default rate as the rule: how many applicants can the model approve?
# Note: this cutoff is found by searching the holdout's own outcomes for the
# largest approval count that keeps the default rate at or below the rule's, so
# the result is optimistic (see the note after the tables).
rule_rate  <- mean(ho$default[!rule_decline])
safe_first <- ho$default[order(ho$prob)]
approve_n  <- max(which(cumsum(safe_first) / seq_len(n_ho) <= rule_rate))
same_default <- tibble(
  `Default rate held at` = pct(rule_rate, 2),
  `Rule approves`  = pct(1 - k / n_ho),
  `Model approves` = pct(approve_n / n_ho),
  `Extra approvals per 10,000 applicants` = num((approve_n - (n_ho - k)) * per_10k)
)

Interpretation. At the same approval rate, the model-based policy approves loans with a lower default rate than the rule, and it still approves most of the applicants with no bureau record whom the rule turns away entirely. This is the more defensible of the two comparisons: the model only has to choose which applicants to decline, and the number declined is fixed by the rule.

Caution on the same-default-rate comparison. The second table should not be used as a headline result. Its cutoff was chosen using the holdout outcomes, by searching for the largest number of approvals that keeps the observed default rate at or below the rule’s. A cutoff tuned on the same data it is evaluated on overstates how well it would hold up on new applicants.

5. Limitations

  • Retrospective, not prospective. Every policy is applied to historical applicants with known outcomes. A deployed policy would face new applicants and changing conditions.
  • Issued loans only. Outcomes exist only for loans Home Credit actually issued, so this analysis cannot show how previously rejected applicants would have performed.
  • No costs. Defaults avoided are counted, not valued. Lost revenue from declined good borrowers, loan sizes, and pricing are not modeled, so no financial savings are claimed.
  • Fairness not assessed here. Age and gender are among the model’s influential predictors (see modeling.qmd and 02_personas.Rmd). The project’s model card (model_card.qmd) assesses fairness separately, at its own 0.25 threshold. It finds approval gaps by gender and education, and direct use of gender, marital status, and age that would block real-world use.
  • Association, not causation. The model ranks applicants by characteristics associated with default; it does not identify causes.
